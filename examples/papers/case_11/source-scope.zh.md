## 分析定义

以下按优先级编号，j<i 表示任务 j 的优先级高于任务 i。

p.2 §2 的两个初步测试，在 D_i>0 下可改写为：

```text
测试 (1): C_i + Σ_{j<i} ceil(D_i / T_j) C_j ≤ D_i

测试 (2): C_i + Σ_{j<i} [floor(D_i / T_j) C_j
                       + min(C_j, D_i - floor(D_i / T_j) T_j)] ≤ D_i
```

原文以除以 D_i 的形式表达，并说明这两个测试充分但一般不必要。平台应保留原式与规范化表达的映射。

pp.3–4 §2 与 Fig.3 的迭代定义为：

```text
I_i(t) = Σ_{j<i} ceil(t / T_j) C_j
t_0 = Σ_{j≤i} C_j
```

每轮检查 I_i(t)+C_i≤t；若不成立，则更新 t 为 I_i(t)+C_i。Fig.3 随后检查 t>D_i，并在越界时拒绝该任务。前面的接受式成立也不能绕过截止期检查；全部任务均通过才是任务集接受。

实现时可以考虑把截止期检查提前，但应将重排与原伪代码的对应关系列入方法合同。算法终止、整数步数界和调度保证分别确定命题，时间域依据用户已确认的建模选择，不能仅由原文的迭代步数说法推出。

## 已选定的主要目标

用户选择 Fig.3 迭代测试的接受充分性，并确认整数时间、零星任务、空初态、执行需求上界、确定 DM 全序及无阻塞/自挂起/额外开销等条件。

> 在选定模型中，若所有任务均通过 Fig.3 对应的迭代测试，则每条合法释放序列中的每个作业均在其相对截止期内完成。

这是量化任务系统与合法运行轨迹的方法级目标。其身份、服务端点、测试接受语义和具体形式化选择由 [数学合同](../../../docs/contracts/case11-integer-dm-soundness.zh.md) 固定。具体任务集的数值验证另作为实例检查。

整数范围、正值、同截止期顺序和模型具体化通过 D12—D13 登记。形式编码遇到需要额外限制的情况时，重新说明影响并确认目标变体，不把库的附加前提静默并入原目标。
