# autoRTA prototype

<!-- impeccable:product-schema 1 -->

## Platform
web

## Users
Real-time systems researchers reviewing models, analysis methods, and proof goals from papers or manual input.

## Product Purpose
Make the next action clear while preserving the relationship between source material, mathematical decisions, derivation, and checked evidence.

## Operating Context
The user selected the research-workbench direction on 2026-11-17 and authorized three clickable screens: projects, source review, and derivation. Existing UI is plain HTML/CSS/JavaScript. This iteration is browser-local demonstration only; no backend or model service is connected.

## Capabilities and Constraints
PDF selection and manual entry are both available as prototype interactions. Uploaded files remain in browser memory and are not extracted. Case 11 is a labeled demonstration. Its integer-time scope is a user choice, not an asserted quotation. Simulated proof states must never claim a real Rocq check or completion of the main theorem. Reload resets all prototype changes. Existing application files and evidence remain intact.

## Brand Commitments
Research-workbench layout, concise Chinese, obvious next steps, a central bidirectional reasoning graph and on-demand details. References accepted by the user: Linear's project organization, Elicit's source comparison, Dify's node inspection, and proof-tool detail panels.

## Evidence on Hand
Existing case_11/source.pdf and its previously rendered page 4. Scenario values are marked as examples. No new analytical result is claimed.

## Product Principles
One next action per task. Name actions in plain language. Keep source and scope accessible. Separate demonstration progress from proof evidence. Use only necessary validation.
