## 第一项工作：建立可检查的模型与目标样例

工作包 W01 接收已选定的论文、整数零星 DM 模型和 Fig.3 接受充分性目标，交付能够在真实工具链中读取与类型检查的模型和目标，以及明确的库材料策略。

| 子项 | 操作 | 交付与完成条件 |
|---|---|---|
| W01-a 工具链核实 | 验证已有 WSL/Rocq 线索，核对实际工具与库版本 | 新项目保存本次版本、最小编译及独立检查日志，历史记录单独标注 |
| W01-b 材料范围 | 核对需要的基础定义与通用引理，识别覆盖目标的现成 RTA 定理及包装 | 允许/排除项清单含类型、来源、版本、摘要和依赖；目标输入不含原证明路线 |
| W01-c 模型与目标编码 | 将合同中的到达、服务、DM 调度、测试和量化范围映射为形式定义 | 精确主要目标声明通过类型检查，每个前提有合同来源；开放主目标明确为未证明 |
| W01-d 边界与样例 | 保存 C01—C08 输入及预期，准备一个简单有效证明和错误目标/额外假设样例 | 有可复查的算术、端点和目标检查材料；辅助样例不计为主要目标完成 |
| W01-e 最小运行入口 | 为上述样例建立单一开发命令与必要配置，记录输入和产物 | 可重复执行同一检查，错误可定位；只创建被这些入口需要的文件 |

W01 完成时，开发者应能演示：加载一个固定数学目标，运行真实检查器处理有效的小证明，拒绝目标错配和不允许的假设，并明确显示主要目标尚未证明。此时可以确认工具链与证据接口是否适合继续开发。

W01 不要求提前确定所有 Web 组件或数据库表。优先验证现有工具线索；若确需安装或调整系统，先给出具体变更与原因，再按实际权限执行。

旧 `autoRTA/toolchain/opam-switch.export` 的实测 SHA-256 为 `d1a949b7ef0426847a6170e03b067226a47040a14b791219e5a4926b62507b1c`，与旧配置一致。但其中 Prosa pin 指向旧 WSL 本地源码路径，跨环境重建仍需固定可获取的源码和摘要。静态登记不等于当前环境可用，也不等于完整可重建环境锁。

该核对没有安装软件、启动 WSL/Docker、运行证明或调用模型 API。

## 首版范围的追踪方式

每个工作包记录输入版本、实际变更、完成证据、未解决问题和下一个可执行步骤。新增模型条件、目标范围或资料使用规则时更新合同与相应决定；实现细节在任务记录中说明。

W01 的模型与检查入口、W02 的证据检查和修订存储均已建立。W03-a 已建立 PDF 数据结构、逐词来源定位、重复导入及重开接口。W03-b 已从实际 case_11 来源匹配模型、分析方法与候选目标，并保存不可变草稿；它不等于通用论文语义理解或 A24 完整验收。W03-c 已接通本地 Web 的来源核对、字段修订、目标选择与上下文冻结。W03-d 已完成固定 case_11 合同的精确形式映射，保留来源、修订、全部所选目标与不支持项；使用独立回执记录对应检查，旧冻结的 mapping_required 字段保持不变。目标保持未证明。W04 已完成本地规则执行的独立双向图、显式对齐、联合前提、路线历史和真实 W02 证据组合。W05-a 已完成本地规则反馈提案，保存原始意见、原图和来源绑定，展示明确 before/after、候选与所选路线影响、待检查任务；原图和证明状态保持不变。W05-b 已接通精确数学确认、采用、独立预算及关联新运行，支持兼容回执复用、依赖变化重检与部分结果保存；真实检查了服务上下界对原桥接义务的联合充分性。W05-c 已实现固定版本的父子运行比较，区分数学内容、实际证明、路线闭包与用量变化，保留旧比较及原始记录。W06 已推进六个通用服务引理和服务上界的真实证明检查，保留服务下界的容量见证义务，详见 [W06 记录](../development/w06.zh.md)。下一步证明任务级工作量与逐作业容量之间的联系；主要目标与正式证据导出包仍未完成。模型驱动的搜索在提供方与预算配置后接入。暂未支持的数学变体继续保留独立缺口。
