## 首个验收案例与完成定义

用户选择 case_11 论文《Hard Real-Time Scheduling: The Deadline-Monotonic Approach》作为贯穿案例，材料与文件摘要见 [开发样本](../../examples/papers/case_11/README.md)。文本层已经检查；公式和版面的平台提取能力仍需验收。

[数学合同](../contracts/case11-integer-dm-soundness.zh.md) 固定首个主要目标 `case11-fig3-acceptance-soundness-int-v1`：在已确认的整数零星 DM 模型下，所有任务通过 Fig.3 迭代测试，蕴含所有合法作业按期完成。它量化任意合法释放与允许执行需求，不能缩成同步轨迹、有限仿真或一个具体任务集。

论文未明确整数时间与同截止期排序。D12—D13 已选择整数 tick 和固定任务顺序等建模细节，登记为明确的形式化范围；[原文核对](../../examples/papers/case_11/source-scope.zh.md) 保留论文事实与这些选择的区别。必要性和 DM 最优性为独立候选目标。

发布验收要求至少一个预先登记的主要目标获得完整形式证明，通过精确目标、实际依赖、假设、材料策略和独立重检。当前主要目标为上述接受充分性目标，辅助引理分别报告。若目标变化，保留原目标并登记用户确认及变体适用范围。

case_11 是本平台开发样本，保留使用历史。后续泛化评测另选并登记材料，不能以开发样本结果代表未见论文的自动完成能力。

## 首版用户主流程

1. 用户在本地 Web 工作台创建分析项目，导入一篇数字版论文 PDF。
2. 平台保存原文件与内容摘要，提取正文、公式、表格、模型定义、调度约定、分析方法和候选保证。
3. 工作台展示候选目标及其来源。用户选择一项或多项，平台记录选定范围。
4. 平台整理 MSA 并生成 IR，将每个目标和假设对应到来源。实质性语义歧义或范围调整进入人工确认。
5. 平台基于同一固定上下文独立执行前向和后向推理，再进行语义对齐、桥接和依赖补全。
6. 平台构造形式证明并检查，分别记录条件充分性和完整节点证据。
7. 数学与工具反馈自动返回负责阶段，经过修订后继续检查。需要用户决定的数学变化展示原因、影响及选项。
8. 工作台持续展示各所选目标的状态、缺口、轮次与成本，导出包含完整或部分结果的可追溯报告。完整证据包的发布条件与一般运行报告分别判定。

用户可以纠正输入与目标，或提交自然语言推导反馈。达到预算或本轮结束仍有未完成目标时，保存部分结果，用户调整后开启关联的新运行。具体运行限额随执行环境确定。

## 人工编辑与推导反馈

首版允许纠正抽取文本、公式、模型条件和目标。修改保留原始 PDF 与来源定位，生成新的抽取、上下文或目标修订。提交前展示变更、解释和受影响对象；范围变化的确认可以合并到这次提交中，确认内容与变更摘要绑定。

运行读取固定快照。用户修改模型或目标后，既有运行及其证据仍对应原版本；使用新版本继续工作时建立关联运行。改变目标条件或保证的修订还需登记目标变体，保留原目标。

推导工作台允许针对目标、候选节点、对齐关系或缺口提交自然语言反馈。平台记录反馈原文、引用版本和处理去向，形成修订提案，通过既有结构校验与证明检查后更新相应状态。反馈提出的数学结论仍是待检查内容，新增假设或改变目标范围时遵循 D02 的确认规则。

首版图与证明视图提供查看、定位及反馈入口。直接编辑引理结构、图连接和 Rocq 脚本属于后续交互扩展。开发者构造测试夹具或检查器接收证明产物，不等于首版用户拥有这些编辑入口。

## 部分结果与关联运行

一次运行达到预算或本轮策略结束后，保存各所选目标的状态、已检查证据、开放义务、输入版本和用量。用户可以调整预算、修订输入或补充反馈，创建带父运行引用的新运行。

新运行固定自己的上下文、目标、策略和预算。继承产物逐项保留来源；旧证据只有在精确目标、上下文、实际依赖和检查策略匹配时才能关联，发生变化的部分标为待重检。新增证明与复用证据分别记录。

延续历史双向图的修订任务登记继承版本及反馈输入；新的首轮双向推理仍遵守初始输入隔离。不能把已读取另一方向历史的修订过程登记成独立首轮。

每次运行分别记账，关联运行视图同时显示单次和累计已知消耗。旧运行中尚未确定的用量保持待核对，不能因开始新运行而清零。新预算在启动时显式设定，历史费用不作为新运行重复记账。

比较视图按目标身份与修订对应，展示模型/目标变更、已完成目标、开放缺口、证据继承、反馈处理和费用差异。目标范围发生变化时明确标注，避免将不同保证的完成情况直接当作同一目标的进步。

同一冻结输入下的技术中断可恢复原运行并保留账本。已经终止的运行继续工作，或需要改变模型、目标、策略及预算时，使用关联新运行。人工确认后无需改变冻结输入的任务，可以在原运行继续。

## 论文提取与推理输入合同草案

原始论文、提取结果与推理可见材料分别保存。原文件提供完整来源供用户查看，推理任务读取筛选后的模型、调度约定、分析表达式、算法描述与所选保证。

论文中的证明段落、参考推导和作者辅助引理的使用依据需要按内容角色检查。作为模型或分析定义不可缺少的条件可以提取，但必须记录其来源与角色。某项条件只有在证明文字中出现、且作用不明确时，提出语义问题并记录处理结果。

提取阶段能够读取完整论文，独立构建的约束落实在传递到前向、后向、对齐和证明构造的材料上。采用独立调用上下文、来源片段清单和输出核查控制传递范围。提取模型的概述也需要核查，防止把原文证明路线转述成推理输入。

每次推理请求保存实际使用的片段和生成摘要。该策略控制任务中提供的信息，预训练知识的影响在评测解释中单独说明。

公式、表格、脚注和目标条件的来源应能定位到原 PDF 页码及对应区域或稳定片段。阅读顺序、上下标、取整、负号、量词、索引和单位异常需要可见诊断。解析系统的置信分数作为核对提示，数学解释通过明确语义与证据建立。

数字版 PDF 的文件大小、页数、语言、加密与损坏文件处理，以及复杂图片公式的支持范围，随选定样本进一步确定。

## 证明库与模型 API 策略

D14 允许基础定义和通用引理，首个工作包冻结具体符号及依赖清单。已覆盖主要目标的 RTA 定理、等价结果及其包装同时限制推理可见资料和最终证明依赖。形式证明有效但材料策略不符合的结果分别记录，不计为独立构建验收通过。细节见数学合同。

D15 允许配置外部模型 API；论文原文件、抽取、项目状态、证明证据和运行记录保存在本机。任务可发送必要文本、公式或页图，实际发送内容和任务用途形成可审计清单。提取任务与独立推导任务分别遵守来源角色及材料范围。

首次真实调用前配置提供方、模型和费用/调用限额，运行冻结所用配置。凭据以本地配置引用，不进入提示、普通日志或证据包。配置缺失时返回明确状态，可继续进行本地核对和工程回放。本次规格工作没有发起模型 API 调用。
