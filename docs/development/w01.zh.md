# W01 开发与复现说明

2026 年 11 月 5 日。W01 是已确认数学合同的最小实现，当前入口运行固定、已审阅的样例。主要目标仍未证明；本工作包不接收任意生成脚本，也不调用模型 API。

## 运行

在 Windows PowerShell 中：

```powershell
Set-Location 'C:\Users\zhenghui\Desktop\autoRTA-platform'
.\check.ps1
```

在已经配置对应 opam switch 的 Linux/WSL 中：

```text
python3 tools/check_w01.py
```

入口使用 [工具配置](../../configs/toolchain.json)，不自动安装软件或改动现有 switch。每次运行创建独立的 artifacts/w01/时间戳目录，包含源码副本、编译产物、命令、日志、依赖摘要、环境快照与 report.json。[latest.json](../../artifacts/w01/latest.json) 指向最近一次运行，需同时查看状态；旧失败记录保持不变。

运行成功的含义是 W01 检查通过。报告独立列出主要目标声明的 typechecked 状态和 unproved 证明状态。进程失败或超时不能转成目标证明成功。

## 合同到代码的映射

| 合同内容 | 形式定义 | 解释与约束 |
|---|---|---|
| 有限任务集、正整数 C≤D≤T | Task、TaskSet、task_wf、taskset_wf | 列表位置充当固定任务身份 |
| DM、相同 deadline 固定排序 | dm_ordered，调度中的 job_task 比较 | 列表按截止期非降序，位置形成严格任务顺序 |
| 任意有限或无限合法到达 | Arrivals、legal_arrivals、separated | 自然数 ID 到可选作业的映射；任意不同同任务作业至少间隔 T |
| 空初态 | 自然数释放时间与 service_from 的零初值 | 允许在 0 释放，不存在负时刻积累的服务或未完成作业 |
| 执行需求上界、零需求 | bounded_demands、ready | 0≤e≤C；零需求从不就绪 |
| 服务区间和截止期端点 | service_from、all_deadlines_met | 只累计 release≤u<t 的服务；在 deadline 恰好完成有效 |
| 单处理器、完全抢占、工作保持 | Schedule、valid_dm_schedule | 每 tick 一个作业；不能执行未就绪作业，有就绪作业不能空闲 |
| 同任务可能重叠 | valid_dm_schedule | 只要求最高优先级任务，可选其任意就绪作业；不加入 FIFO 或无重叠前提 |
| Fig.3 初值、工作量和 guard | initial、workload、iterate | 初值为自身与高优先级 C 之和；t>D 不能接受 |
| 数学接受 | accepts_from、fig3_accepts | 存在有限合规轨迹，全部任务接受 |
| 主要目标 | case11_fig3_acceptance_soundness_int_v1 | 量化所有任务集、到达和调度；实际需求在作业字段中量化 |

原文判断顺序和规范化 guard 先行表达的接受关系通过 accepts_from 描述。已证明的 iterate_accepts_sound 只说明可执行迭代接受能产生该数学接受证据，尚未证明调度充分性、总终止性、原伪代码与规范化执行器的完整等价或一般响应时间安全界。

check_task/check_at 是形式模块的计算辅助入口，调用者仍需建立 taskset_wf。它们尚未构成带通用输入校验的产品分析入口。非整数参数由 nat 表示排除；JSON/PDF 的字段诊断属于后续输入模块。

## 库材料策略

W01 的直接基础依赖只有 Stdlib 的 PeanoNat、List 和 Bool。锁定清单记录其实际传递依赖；所有 Prosa、MathComp、自动证明插件及未登记库均不在本工作包的导入集合。当前没有被允许的现成 RTA 定理。

用到的典型通用引理包括 Nat.add_0_r、Nat.ltb_ge、Nat.leb_le、Nat.leb_gt、Nat.le_refl、Nat.nle_succ_diag_l、Nat.lt_irrefl；其类型适用性由对应证明的真实编译检查。小型正例直接证明 forall n, n+0=n，与主要调度目标分别登记。

每次独立内核检查读取实际加载的 .vo 清单。只允许本次项目构建目录与已冻结的 Corelib/Stdlib 文件，随后核对 .vo 摘要及可取得的 .v 源码摘要；未知或变化依赖会使检查失败。具体库文件记录在 lock 中，运行的实际闭包记录在 report 中。

这是一套小范围、固定来源的模块策略。面向任意模型生成代码的符号级资产审核、进程隔离与受控文件访问属于 W02 及后续工作，不能将当前脚本直接当作公共证明执行服务。

## 证据检查顺序

1. 检查实际环境版本，并保存二进制摘要和本次 opam export。
2. 复制受检查源码到新的构建目录，用完整 rocq compile 编译。
3. 独立生成目标绑定声明，将 Candidate.candidate 当作固定 smoke_target 的证明项。
4. 运行 rocqchk 递归检查依赖，不使用 admit、norec、vos 或跳过证明的编译选项。
5. 核验实际依赖、检查器理论设置及不安全标记，并用 Print Assumptions 查询目标的实际假设。
6. 复制必要 .vo 到另一个目录，以新进程重检正确证据和模型样例。

负例即使能编译，也可能因目标不符、未允许假设或不安全检查设置被拒绝。Print Assumptions 由单独生成的审计文件执行，不能只凭候选源码中的自报输出认定通过。

## 环境复建与适用限制

[最小 opam 规格](../../toolchain/w01.opam) 固定 OCaml 4.13.1、Rocq 9.0.0 和 Stdlib 9.1.0。安装包原始元数据保存在 [toolchain/packages](../../toolchain/packages)，其中包含可取得的源码位置和校验信息。完整已安装 switch 导出按运行保存，可能包含 W01 未使用的包及本机路径，不能直接称为跨机器锁。

当前实际验证的是现有环境，以及同机独立目录/进程重检。尚未在全新机器上安装并复现；library-lock 同时包含本机编译产物摘要，在另一构建环境中可能需要经过审查更新。后续可移植性验证必须保留源码校验和真实重检结果。
