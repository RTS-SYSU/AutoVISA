# W02 开发与复查

W02 回答一个问题：对给定目标的**这一次修订**，有哪些证据，今天还能不能用？可直接运行的例子叫 `joint-demo`。它是算术命题与 `True` 的合取，和论文主要目标分别登记。

## 从哪里开始看

1. [验收案例](../../tests/acceptance/w02_cases.py) 中的 `exercise` 是一个完整使用例。先读从创建 `p, q, g` 到 `service.compose` 的几行，再看后面的修订。
2. [应用接口](../../src/platform_core/evidence/service.py) 提供 `context`、`goal`、`prove`、`compose`、`history`。创建首版不传 `parent`，修改必须提交自己读取的父版本 ID；过期编辑返回 `revision_conflict`。
3. [证明输入](../../src/platform_core/evidence/terms.py) 登记可命名的命题、证明常量、类型及来源。[检查器](../../src/platform_core/evidence/rocq.py) 生成候选和精确类型包装，调用 Rocq、独立内核、假设审计和符号依赖查询。关键判断旁均有英文注释。
4. [事务与对象存储](../../src/platform_core/evidence/storage.py) 和 [数据库约束](../../src/platform_core/evidence/schema.sql) 实现只追加历史、并发修订和按摘要取件。

## 英文代码注释约定

Python 模块和类说明职责。函数和方法（包括内部辅助函数）用英文文档字符串说明调用约定。用 `@param name` 逐项说明参数的含义、单位、顺序或允许值，实例参数 `self` 省略。返回结果用 `@return`，上下文管理器提供的值用 `@yield`，调用方需要处理的异常用 `@raise ExceptionType`。没有返回值的过程直接写清它保存或改变了什么。例如，`Evidence.compose()` 返回尝试 ID，拒绝原因通过这次尝试的回执读取。

类状态用 `@ivar`，模块常量用相邻的 `#:`。局部变量在赋值附近用英文说明其领域含义。相关变量可以一起说明，尤其要区分目标修订 ID、尝试 ID、文件摘要和参数顺序。PowerShell 入口用内置帮助格式，Bash 入口说明参数和运行环境，SQL 在表、字段和触发器旁说明约束。检查器源码和表定义属于环境摘要的输入，因此这些文件调整注释后也要重新运行验收。

## 本地运行

在项目根目录的 PowerShell 运行：

```powershell
.\check-w02.ps1
.\check-w02.ps1 -Goal joint-demo
.\check-w02.ps1 -Goal case11-fig3-acceptance-soundness-int-v1
```

第一条使用真实 PostgreSQL、Rocq 和 rocqchk 运行验收，再将数据库备份恢复到第二个临时实例。后两条读取最近一次成功运行，校验报告、备份摘要，在私有数据库中恢复，并按当前项目环境查询。查询输出是 JSON，可以使用 `ConvertFrom-Json` 查看 `state`、`routes`、`attempts` 或 `issues`。

当前机器已准备所需组件。新机器需要先按 W01 配好 Ubuntu 中的 opam switch。数据库侧可使用具有 initdb、pg_ctl、pg_dump、pg_restore 的本地 PostgreSQL 和系统 Python 的 psycopg2，或在 Ubuntu 22.04 的项目根目录运行 `bash tools/prepare_w02.sh`，从配置的 Ubuntu 仓库下载并解包项目专用组件。后者需要网络，不使用 sudo。常规检查不联网、不启动系统服务、不调用模型 API。测试数据库只监听当前用户私有的 Unix 套接字。

## 如何解读结果

| 观察值 | 含义 |
|---|---|
| `conditional` | 已检查同一上下文下的联合前提到目标的蕴含。查询列出还缺少完整证据的前提修订。 |
| `partial` 且 `missing: []` | 前提都已各自证明，还需对证明项的组合执行检查。 |
| `complete` / 当前 `checked` | 当次精确类型、内核、真实依赖及假设检查通过 / 当前目标仍有可用的完整回执。 |
| 历史 `complete` 且 `version: stale` | 当时检查通过。现在改变了目标、上下文、必要依赖或环境，或必要产物已不可用；查看 `issues` 的旧、新修订及依赖路径。 |
| 尝试的 `code: null` | 已登记但未写入结果，可能仍在运行或被中断。不能计为成功。 |

同一目标可有多条路线。修改前提只影响依赖该修订的路线。旧回执不被更新或删除，查询在 PostgreSQL 的同一个读快照中计算当前可用性。两个开发者基于同一父版本编辑时，只接受一次追加。

上下文包含固定工具与模型内容摘要，以及显式模型限制。`hypotheses` 中的限制会编码为定理的前提。未完成的义务不能作为全局公理使用。候选只接收登记的结构化表达式与基础常量，不执行外部提交的任意 .v、插件、策略脚本。当前语法覆盖本工作包样例与 case_11 目标引用，不能表达完整调度理论的任意推导。

## 产物与信任边界

每次检查生成 `artifacts/w02/<run>/report.json`。成功运行另存 PostgreSQL 备份 `history.dump`、目标查询 `joint-history.json` 和内容目录 `objects/`；`artifacts/w02/latest.json` 只指向成功运行。`attempts[].manifest` 是回执清单的 SHA-256，本地同名对象内的 `files` 将源文件、.vo、命令日志映射到对象摘要。`logs/assumptions` 和 `logs/symbols` 是 Rocq 自身的输出。`libraries` 记录内核实际加载的基础库 .vo 及摘要，与 W01 清单对照；它是模块加载范围，不等于定理使用了其中所有引理。

回执以本机模型源码、固定的基础库清单、Rocq 工具、检查器实现和本地数据库管理员为信任边界。应用层拒绝用户自报的证明成功，也不接受任意名称作为可复用定理。它不提供对恶意机器管理员的防护。W02 的本地备份恢复不同于 W06 面向第三方的独立证据包。Web 入口、语义对齐、材料泄漏检测和主要目标证明仍属于后续工作包。
