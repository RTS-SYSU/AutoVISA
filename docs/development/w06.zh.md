# W06：服务界与调度桥接证明进展

本轮推进固定 case_11 整数时间 DM 合同下的证明。**W06 整体尚未完成；主要目标仍未证明。** 本次交付的是服务上界完整证明、服务下界的通用调度引理、保留开放前提的精确桥接，以及真实检查产生的关联运行与证据。

## 形式化结果

源码：[Service.v](../../proofs/Service.v)。只引用既有 Model 与基础自然数、布尔库，不使用现成 RTA 主定理，不增加公理或 admitted 证明。

| 引理 | 已证明的陈述 |
| --- | --- |
| service_monotone | 固定作业和释放点，累计服务随观察端点单调不减 |
| counters_before_release | 释放前和释放端点的自身、非自身服务均为零 |
| service_never_exceeds_demand | 有效调度下，任意时刻的累计服务不超过实际需求 |
| pending_dispatch | 作业就绪时，必有一个已存在且就绪的作业执行，其任务优先级不低于该作业 |
| pending_window_balance | 作业在区间末仍未完成时，从释放到该端点的自身服务与非自身服务之和等于区间长度 |
| capacity_implies_service_lower | 截止期内存在足够容量的具体区间，就能推出截止期服务下界 |

`interference_from s id r t` 按半开区间 `[r,t)` 计数调度给其他作业身份的占用时间。它包含同任务的其他作业，也不预先排除释放于区间之前的作业；这不是已经证明的高优先级分析工作量。

所有函数、参数与新增变量采用英文 Javadoc/JSDoc 风格文档；Rocq 引理的前提、参数、时间端点和结论均有英文说明。

## 下界还缺少什么

对于每个作业，容量见证的精确形状为：

~~~text
exists duration,
  duration <= task_deadline p /\
  interference_from s jid (job_release j) (job_release j + duration)
    + job_demand j <= duration
~~~

这个命题是**待证明的节点**，没有作为新模型条件写入上下文。仍需从原有 taskset_wf、legal_arrivals、bounded_demands、valid_dm_schedule 和任务工作量见证推出它。

已检查的充分路线是：

~~~text
一般“不超额服务”引理 → 原服务上界（完整）
容量见证（开放） ∧ 容量到服务下界引理（完整） → 原服务下界（条件证明）
原服务下界 ∧ 原服务上界 → 原调度桥接（条件证明）
接受轨迹的任务见证 ∧ 原调度桥接 → 原主要目标（条件证明）
~~~

数学条件、目标、量词和截止期端点均保持原样。核心缺口是任务级分析与真实忙区间之间的论证，尤其是已有干扰作业、同任务积压以及任意合法释放轨迹下的计数。当前没有将简单的逐任务 ceiling 工作量公式直接当成实际非自身服务上界。

下一轮应从该缺口展开：建立适用的优先级忙区间和归纳不变量，再证明释放数量、累计执行量与任务工作量见证之间的联系。任何新增限制须单独登记并由人确认，不能用来替代原合同的证明。

## 平台使用

1. 在 W05-b 已拆分上下界的运行中，选择“调度桥接”或任一服务界节点。
2. 提交“推进服务上下界证明”，也可选择同名处理方式。

4. 新运行保存真实 Rocq 回执，上界闭合；容量见证、服务下界、调度桥接和主要目标保持如实状态。
5. 用父子运行比较查看上界证明与开放义务的变化，点击证据查看精确命题、生成源码和当时的本地模型源码。

已有服务计数路线不会重复添加。追加检查预算可以再次采用原提案建立新的关联运行；后续数学分解仍需实现对应的新规则。
