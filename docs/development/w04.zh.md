# W04 双向推导与对齐工作区

2026 年 11 月 11 日

W04 已实现 case_11 的本地规则版推导工作区：从检查通过的 W03 映射启动两个独立方向，生成候选图，实例化并检查连接，保留联合前提，选择证明路线，保存真实证据与开放义务，并在 Web 中查看。

开发采用 mattpocock-skills:codebase-design 的 deep Module 方法。DerivationWorkspace 提供小型 Interface，Web、CLI 和集成验收共用它；类型化命题、图展开、对齐、证据组合和版本存储集中在 Implementation 内。证明检查与组合直接复用 W02。当前只有本地规则实现，因此没有提前引入多种模型 Adapter 的抽象层。

## 直接运行

在项目根目录执行：

~~~powershell
.\derive.ps1 -Check
.\start-workbench.ps1 -W04Demo
~~~

第二条从最新成功验收建立独立演示目录。看到 ready 后打开 http://127.0.0.1:8765 ，选择演示项目的“变更与冻结记录”，从检查通过的映射点击“进入双向推导”，再选择已有运行。演示中的数学确认有独立夹具标记，不写入正式项目。

正式使用从已核对、已冻结并完成映射的上下文开始：

~~~powershell
.\start-workbench.ps1
~~~

进入映射对应的推导页面，点击“运行双向推导”。生成的图可点击查看完整命题、来源页和证明回执；主要目标的下拉框可切换见证路线与直接后向路线。选择另存为修订，刷新后恢复。

停止工作台后，可用同一正式目录执行 CLI：

~~~powershell
.\derive.ps1 -Mapping '<W03 映射回执完整 ID>'
.\derive.ps1 -Run '<已有推导运行 ID>'
~~~

导出目录为 artifacts/w03/derivations/，含 run.json 和数据库备份。推导与形式检查使用现有本地工具链，首次运行通常需要数分钟。

## 本轮实际推导

前向方向从固定的分析定义产生并证明三个通用事实：

1. 有限接受轨迹给出某个 w，使 w≤D 且 workload(w)≤w。
2. 接受轨迹的起点不超过任务截止期。
3. 工作量至少包含自身执行需求上界。

后向方向为主目标保留两条充分路线：

- 逐任务工作量见证，加上“工作量见证蕴含合法调度的截止期保证”桥接义务，共同推出主目标。
- 直接按任务、作业及绝对截止期分解目标。该路线自身可采用，无需先找到前向支持。

随后对齐阶段把通用接受轨迹事实实例化为逐任务义务：

~~~text
hp := firstn i ts
p  := p
t  := initial (firstn i ts) p

条件：fig3_accepts ts；nth_error ts i = Some p
~~~

对齐的蕴含方向与实例化单独保存。W02 先检查该连接的条件充分性，再应用已证明的前向事实，取得“每个通过测试的任务都有工作量见证”的完整证明。

本次实际获得 **4 个局部完整证明、3 个条件充分性回执**。主目标所需的调度桥接义务仍开放；Fig.3 精确性等未编码目标仍作为独立根节点显示。

## 图与证明状态

每条 Derivation 保存一个完整、有序的 premises 数组与一个 conclusion，表达联合前提。替代路线是独立 Derivation。选定图按结论选择一路，记录其剩余开放叶节点。

- 候选提出：规则执行已形成数学陈述。
- 条件充分性通过：真实 Rocq 已证明联合前提能够推出结论。
- 节点完整证明：全部前提具有适用证据，并经 W02 compose 实际组合、检查。
- 主目标完成：必须取得该目标本身的完整回执。

源代码用带类型的存在量词、合取、全称量词和函数应用表达命题。生成的证明构造有独立声明类型，再通过 W02 的目标包装检查；改变截止区间或反转对齐方向会发生实际目标类型不匹配。

每个通过的回执保存 .v/.vo、工具日志、精确目标、假设审计和实际加载的依赖闭包。检查使用现有基础库策略，不使用现成 RTA 主定理。

## 输入、来源与历史

两个方向分别取得共同输入的独立副本。各自保存请求内容摘要、方向、空 peer_inputs、输出图及执行事件；对齐阶段在两侧输出之后运行。输入只包含已冻结的模型、分析、目标及其来源片段，没有向规则传入论文完整证明。

执行类型明确记录为 local_rules。这是本轮实际执行的确定性规则及证明构造，不是远程模型推理或历史图回放。规则代码与输入均以内容摘要归档，适合重开和独立核验。后续模型驱动的候选搜索可以沿同一图与证据合同扩展。

每个节点保留：
- 映射回执、freeze、核对修订及命题内容身份。
- 对应的语义来源 key，可解析到原文页码、范围与引用。
- W02 目标修订和实际证明尝试。
- 独立的候选归属、对齐实例化及充分性回执。

运行与结果使用只追加记录；路线选择另有 parent 与预期修订。错误目标连接、循环路线和旧页面覆盖新选择均被拒绝。旧图不会因路线选择而改变，数据库恢复后可重开同一图和证据。

## 代码阅读顺序

| 文件 | 职责 |
|---|---|
| src/platform_core/reasoning/statements.py | 带类型命题、工作量见证与后向义务 |
| src/platform_core/reasoning/rules.py | 实际执行的局部证明构造 |
| src/platform_core/reasoning/graph.py | 独立两侧展开、实例化、联合前提与路线规划 |
| src/platform_core/reasoning/service.py | derive、read、history、select、evidence |
| src/platform_core/reasoning/schema.sql | 运行、结果和选择历史 |
| src/platform_core/evidence/terms.py | 接收类型化分析命题及已登记推导规则 |
| src/platform_core/evidence/rocq.py | 固定规则实现与检查环境，复用原有精确目标和依赖审计 |
| web/reasoning.html / reasoning.js / reasoning.css | 交互推导图、路线选择、来源与证据详情 |
| tools/derive.py / derive.ps1 | 同一工作区的 CLI |
| tools/check_w04.py / tests/acceptance/w04_*.py | 实际 HTTP、数据库和 Rocq 集成验收 |

函数、参数、返回值与状态字段采用英文 Javadoc/JSDoc 风格注释；数学变量另注释其任务、时间、作用域和证据含义。

HTTP 入口：POST /api/derive、POST /api/select-route；GET /api/derivation、GET /api/derivations、GET /api/derivation-evidence。推导页面为 /reasoning?mapping=... 或 /reasoning?run=...。
