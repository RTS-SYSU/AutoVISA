C_i 是目标的输入假设。软件证明分析在这些上界下的保证，执行需求测量或 WCET 分析正确性属于另一个问题。

释放模式不要求全体在 0 同步，也不固定周期相位。周期任务只要其实际释放满足对应最小间隔，就属于本目标量化范围。

## 服务与完成的端点约定

调度 σ(t) 指定区间 [t,t+1) 内执行的作业，或为空闲。作业只能在释放后且尚未完成时执行。

```text
service(σ, j, t) = 在所有满足 r_j ≤ u < t 的整数 u 中，σ(u)=j 的次数
pending(σ, j, t) = r_j ≤ t 且 service(σ, j, t) < e_j
meets_deadline(σ, j) = service(σ, j, r_j + D_task(j)) = e_j
```

在截止期时刻恰好完成视为按期完成；[d_j,d_j+1) 内获得的服务不计入按期完成。e_j=0 的作业在释放时完成，且不占用处理器。

同一任务若存在多个未完成作业，调度定义允许选择其中任意就绪作业。本目标不预先假设作业不会重叠，也不把此前作业已按期完成放入全局前提。若后续库适配需要额外 FIFO 条件，应说明其必要性，并按语义变化流程处理。

## Fig.3 的分析测试

任务按上述 DM 全序编号为 1 到 n，j<i 表示更高优先级。采用精确整数算术：

```text
ceil_div(t, T) = ceil(t / T), 其中 T > 0
I_i(t) = Σ_{j<i} ceil_div(t, T_j) × C_j
W_i(t) = C_i + I_i(t)
t_i,0 = Σ_{j≤i} C_j
```

初值是自身及所有更高优先级任务的 C 之和，对应原文 Fig.3。以 C_i 为初值的其他迭代不能无说明地替换本方法。

便于实现的规范化伪代码如下：

```text
check_task(i):
    t = sum(C_j for j ≤ i)
    loop:
        if t > D_i:
            return not_accepted
        q = W_i(t)
        if q ≤ t:
            return accepted(witness=t, workload=q)
        t = q

check_taskset:
    检查每个任务
    仅在所有任务均 accepted 时返回 accepted
```

原 Fig.3 在检查接受式或更新 t 后仍执行截止期检查。这里把 guard 提前，必须保留原文到规范化算法的对应说明，并在方法形式化中建立接受行为的对应；这个重排不允许接受 t>D_i 的点。

分析证据保存初值、每个迭代值、求值结果与停止原因。数学接受谓词要求存在符合更新规则的有限轨迹，且最后满足 t≤D_i 与 W_i(t)≤t。算法终止性作为方法义务处理，不能以资源超时冒充测试拒绝。

软件输出区分：

| 输出 | 含义 |
|---|---|
| accepted | 数学测试接受；调度保证还需绑定已检查的方法定理及实例前提 |
| not_accepted | 测试没有建立本目标的保证；首版仅证明充分性，不据此声称系统一定错过截止期 |
| invalid_input | 参数或模型条件不符合合同 |
| inconclusive | 时间、步骤、内存等执行限额使本次计算未完成 |

## 主要目标声明

记 TaskWF 为上述任务参数与优先级条件，LegalArrivals 为零星到达和初态条件，BoundedDemand 为作业执行需求条件，ValidDMSchedule 为合法执行、DM 优先级和工作保持条件。

```text
对任意有限任务集 τ、合法释放序列 A、执行需求 e 和调度 σ：

TaskWF(τ)
∧ LegalArrivals(τ, A)
∧ BoundedDemand(τ, A, e)
∧ ValidDMSchedule(τ, A, e, σ)
∧ Fig3Accepts(τ)
⇒ 对 A 中每个作业 j，meets_deadline(σ, j)
```

以上是目标规格，并非已检查的 Rocq 声明。形式编码必须显式量化任务参数、合法到达序列、执行需求和所有符合调度定义的 σ。将它缩成一个同步轨迹、一个有限仿真窗口或一个数值任务集，均不满足主要目标。

不允许把全部任务已可调度、全局无 deadline miss、待证干扰界或相同目标的重命名放入目标前提。推导中使用的归纳假设必须在正式证明里建立其作用域和合法性。

## 独立构建与库使用合同

D14 允许基础逻辑、算术、集合、有限求和、调度定义及经核对的通用引理。既有且已覆盖本目标的 RTA 主定理、等价定理及经包装后的证明被排除在本次独立构建验收之外。现成一般 FP 定理若仅需实例化为 DM 即可获得完整目标，也需要按这一规则分类。

开发前建立允许项与排除项清单，记录声明、类型、来源、库版本、内容摘要、依赖和采用理由。符号名或文件名不足以判断资格；边界项依据陈述与实际用途审核。

来源控制分为三处：

1. 从论文传入模型、分析方法与目标，筛除作者证明路线及其转述。
2. 限定推理任务可见的库资料、检索结果和工具读取范围，保存实际输入清单。
3. 检查最终证明的实际传递依赖，识别经中间包装引入的排除项。

数学有效性与材料策略符合性分别报告。形式证明通过但使用了排除项的产物，可以保留其数学检查记录，但不计入首版独立构建主目标的通过结果。材料控制不声称消除了模型预训练知识的影响。

## 小样本与边界检查

任务参数均以 (C,D,T) 表示。以下算术预期已在本地临时计算中核对，尚未执行平台验收或形式证明。

| 编号 | 输入或情形 | 预期 |
|---|---|---|
| C01 | (1,4,4)、(2,5,5) | 第一个任务在 t=1 接受，第二个在初值 t=3 接受 |
| C02 | (2,2,10)、(1,2,10)，相同 D 按给定顺序 | 第二个初值 t=3>D=2，必须不接受；即使 W(3)=3 也不能跳过 guard |
| C03 | 单任务 (1,1,1) | t=1=D 接受；执行 [0,1) 的作业在 1 完成符合截止期 |
| C04 | (2,3,3)、(3,10,12) | 第二个轨迹 5→7→9，在 W(9)=9≤D=10 时接受 |
| C05 | 相邻释放恰好相隔 T | 合法；相隔 T−1 的输入不满足模型 |
| C06 | 某作业 e=0，任务 C>0 | 作业在释放时完成，不分配服务 |
| C07 | 同步与非同步的合法释放 | 都在目标量化范围；有限轨迹演示只用于检查表示 |
